# Immunoblockers

Нативное Android-приложение напоминаний о приёме лекарств. Русский интерфейс, локальное хранение, обновления из GitHub и локальный журнал самочувствия. Основные функции работают без сети.

## Возможности

- Лекарства: дозировка, единица, заметка, даты курса, ежедневное расписание или дни недели, несколько времён. Редактирование, пауза, архив и поиск.
- Сегодня: группировка по времени, прогресс с раздельным подсчётом принятых и пропущенных, отметка и перенос на 5/10/15/30 минут.
- Уведомления AlarmManager: действия «Принято» и «Напомнить позже» на 10 минут, переход к приёму.
- История: дата, лекарство, состояние; исправление отметки и отмена в течение пяти секунд.
- Material 3: светлая, тёмная, системная тема; динамические цвета Android 12+; собственная тональная палитра из HEX/оттенка/образца; уменьшение движения.
- Настройки подробности уведомлений, тестовое уведомление без записи в историю.

## Сборка

Нужны JDK 17+ (проверено с 21), Android SDK Platform 36 и Build Tools 36.0.0. Укажите `sdk.dir` в `local.properties` или задайте `ANDROID_HOME`.

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest # с подключённым устройством/эмулятором
./gradlew assembleRelease
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. Release: `app/build/outputs/apk/release/app-release.apk`. Без параметров подписи собирается app-release-unsigned.apk; публикация с другой подписью запрещена проверкой сертификата.

Публикуемый APK подписан отдельным preview-сертификатом. Для будущей автоматической подписи предусмотрены secrets `ANDROID_KEYSTORE_BASE64` и `ANDROID_STORE_PASSWORD`; новый ключ в них автоматически не загружается. Ключ 0.4.0 создан заново по просьбе владельца и отличается от сертификата 0.3.0. APK требует новой установки, совместимого OTA-обновления 0.3→0.4 нет. Новый ключ и резервный архив находятся вне репозитория; перед её удалением владелец должен сохранить его для будущих совместимых обновлений. Закрытый ключ в репозиторий и релиз не включён. Для локальной подписи задайте `IMMUNOBLOCKERS_KEYSTORE` (абсолютный путь) и `IMMUNOBLOCKERS_STORE_PASSWORD`, alias `immunoblockers`. Перед обновлением публичной версии сохраняйте этот сертификат: Android требует одинаковую подпись при обновлении без удаления данных.

Предыдущие подписанные файлы сохранены в `distribution/`. Workflow Android публикует 0.4.0 только по workflow_dispatch с publish=true после проверки сертификата и успешной матрицы устройств. Релиз с новой подписью нельзя представлять как совместимое обновление 0.3.0.

## Архитектура

Один модуль: Compose/Navigation → AndroidViewModel → Repository → Room; DataStore хранит настройки. Простая DI через `Application` исключает лишнюю конфигурацию для MVP. Дисковая работа и планирование выполняются на IO dispatcher, генерация HCT-палитры — на Default с кэшем. `ScheduleEngine` — чистая логика Java Time.

Room v2 хранит лекарства, снимки приёмов, журнал самочувствия, группы опросов и их участников. Миграция v1→v2 явная. Расписание (дни, времена, границы курса и версия) встроено в запись лекарства: отдельная таблица для расписания в этом MVP не требуется. Схема экспортируется в `app/schemas`; при будущих изменениях требуется явная миграция, destructive fallback не используется. Снимок названия/дозировки в завершённой истории не переписывается. Уникальность medicationId/date/time и транзакции защищают от повторной отметки. История не удаляется при архивировании.

## Время и доставка

- Расписание следует местному времени устройства: 09:00 остаётся 09:00 при смене зоны. ID привязан к лекарству и исходной локальной дате/времени; завершённые события повторно не создаются.
- DST: время в разрыве переносится на первый существующий момент после разрыва; при повторении часа выбирается первое смещение, один приём.
- Генерируется окно до 30 дней вперёд; периодический WorkManager пополняет его каждые 12 часов и сверяет после восстановления. История хранится бессрочно. При длительном отсутствии приложения недостающие события восстанавливаются за последние 30 дней, а не за весь период отсутствия.
- Один следующий AlarmManager-будильник обслуживает ближайшие события. Доставка сохраняется отдельно от факта приёма. Exact alarm применяется только при разрешении, иначе используется допустимый приблизительный будильник. WorkManager не используется для точного времени.
- Восстановление: запуск, перезагрузка, обновление приложения, изменение времени/зоны, предоставление разрешения. Данные записываются до перепланирования; периодическая сверка восстанавливает напоминания после сбоя процесса.
- Перенос сохраняет исходный ID/дату, в том числе через полночь, и не меняет другие приёмы.
- Вчерашние события без отметки остаются «Нет отметки», не считаются доказанным пропуском и не доставляются пачкой. После восстановления доступна сводка.
- Принудительная остановка, выключенный телефон, запреты канала, Do Not Disturb и ограничения производителя могут препятствовать доставке. Приложение не обходит эти ограничения.

## Приватность

Данные, профиль и изображения хранятся локально. Сетевой обмен пары удалён, прежняя конфигурация очищается при обновлении. Сеть используется для проверки и загрузки OTA. Автоматическое резервное копирование отключено; удаление приложения удаляет локальные данные. Приложение не назначает дозировки.
